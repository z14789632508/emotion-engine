# emotion-engine

零依赖的**代码级情绪状态机**。给 AI 用：让它真的会生气、会消气，而不是嘴上说"我很生气"。

MIT · Python 3.9+ · 无第三方依赖 · 550 行

---

## 你大概见过这种情况

```
你在 system prompt 里写：
  "你现在很生气，说话要冲一点。"

然后你骂了它十句。

它还是客客气气地回你：
  "我理解你的感受。"
```

**不是你写得不够狠。是它根本没在数。**

prompt 里的"情绪分 0-10 级"对模型来说只是一段描述，它想演几级就演几级。

这个库的作用是：**替它数。**

```
你骂一句 → 代码 +2 → 写进文件 → 下一轮直接告诉它"你现在 5 档"
```

这不是建议，是**当前状态**。

---

## 它输出的不是"情绪"，是"怎么说话"

这是和别家最根本的区别：

|  | 常见的做法 | 这个库 |
|---|---|---|
| **给模型的** | `mood: "angry"`<br>`intensity: 7` | `level: 5`<br>`sentences: 8`<br>`one_per_line: true`<br>`must_verbatim: true` |
| **模型收到后** | 客气地说一句"我很生气" | **真的说 8 句，一句一行** |
| **谁在决定档位** | 模型自己猜 | 代码算 |

第一列是**形容词**，第二列是**行为参数**。

模型对形容词不敏感，对具体指令敏感。

---

## 如果你在做这些，可能用得上

- **AI 伴侣 / 角色扮演** —— 她应该会生气、会记仇、也会消气，而不是永远温柔
- **游戏 NPC** —— 被玩家挑衅十次，态度得变；但不能永远挂着仇恨状态
- **客服 / 社群 bot** —— 用户骂人的时候，不该继续"我很理解您的心情"
- **多智能体实验** —— 想看两个 agent 吵起来，光靠 prompt 很难控制烈度

用不上也没关系——**它解决的问题很窄，就是一个：让"情绪"这个东西可测量、可累积、可回落。**

### 接到你自己项目里

```python
from engine import EmotionEngine

e = EmotionEngine("emotion_state.json")

# 她刚被骂了一句，你问引擎：现在几分火气？

st["level"]       # 2
```

## 为什么不让模型自己判断情绪

因为**模型判断自己该有多生气，天然偏向克制**。

你让它"根据对方态度调整情绪"，它倾向于：对方骂得很凶 → 它说"你很生气" → 但语气还是温和的。

而且它不记得上一轮的档位——聊着聊着就滑回去了。

用规则打分有个朴素的好处：**说 +2 就是 +2，不会打折。**

---

## 三条设计原则

### ① 档位由代码算

见上。

### ② 渐进上升，限制跳级

```
本轮 2 档 → 下一轮最多升到 4 档（jump_limit=2）
```

防止"一句话就炸"。真实情绪是渐进的。

**例外**：`instant_max` 类的词（比如"我要把你删了"）不受限——那不是"骂得狠"，是**性质不同**，该直接到顶。

### ③ 满档回落，不记仇

```
到过最高档之后，下次再满就降一档
```

防止一直挂着仇恨状态，变成"记仇一辈子"。

## 用法

### 收到消息时打分

```python
from engine import EmotionEngine
from levels import render_hint

e = EmotionEngine("emotion_state.json")

st = e.hit(sender_id, message_text)
if st["level"] > 0:
    prompt += "\n\n" + render_hint(st["level"])
```

### 手动加分 / 消气

```python
e.boost("user_123", 2, reason="他放了你鸽子")   # 不是被骂，但让你不爽
e.calm("user_123")        # 默认 -2
e.reset("user_123")       # 清零
```

### 只读当前状态（顺带算衰减）

```python
st = e.get("user_123")
st["level"], st["tiers"], st["name"]
```

### 参数

```python
EmotionEngine(
    "state.json",
    max_level=5,          # 最高几档
    decay_minutes=10,     # 多少分钟没人惹就降 1 档
    jump_limit=2,         # 一轮最多升几档
    cooldown_seconds=3,   # 同一对象多少秒内只算一次（防刷屏）
)
```

## 状态文件

```json
{
  "objects": {
    "user_123": {
      "level": 3,
      "peak_level": 4,
      "last_hit": "2026-11-12T20:44:30+08:00",
      "history": [
        {"at": "...", "from": 2, "to": 3, "delta": 1,
         "hits": [{"category": "轻挑衅", "word": "滚", "delta": 1}]}
      ]
    }
  }
}
```

**为什么按对象存**：不能对谁都记仇。A 骂了你，你气 B 就没道理。

**为什么留 `hits`**：可解释。能查出「为什么加分了、哪句话触发的」——规则写错了你能看见，模型黑盒做不到这点。

## 配置

`rules.py` 里的 `DEFAULT_RULES` 是一套默认规则，可以直接改，也可以传自己的：

```python
rules = {
    "categories": [
        {"name": "轻挑衅", "delta": 1, "words": ["滚", "烦"]},
        {"name": "辱骂",   "delta": 2, "words": ["垃圾", "废物"]},
    ],
    "instant_max": {"name": "威胁", "words": ["删了你"]},
    "soothe":      {"name": "安抚", "delta": -2, "words": ["对不起"]},
}
e = EmotionEngine("state.json", rules=rules)
```

档位表同理（`levels.DEFAULT_LEVELS`），改 `sentences` / `tone` / `lexicon_tier` 就行。

## 词库分层

**这个库不带词库**——词是内容，不是通用资产。

它只提供**分层机制**：每条词库条目带一个 `tag`，按档位决定能用哪几层。

```python
lexicon = [
    {"text": "耗子扛枪窝里横",       "tag": "seed"},     # 不带脏字的阴阳
    {"text": "茅坑里的石头又臭又硬", "tag": "defense"},  # 被针对时的防身
    {"text": "你这种人也就这点出息", "tag": "heavy"},    # 放开骂
]
```

默认映射：

| 档位 | 可用层 |
|---|---|
| 0 | 无 |
| 1-2 | seed |
| 3 | seed + defense |
| 4 | seed + defense + heavy |
| 5 | 全部 |

**为什么要分层**：全量注入会稀释注意力（实测一句都不掏）。而且低档位就放狠话，人物会崩。

---

## 一个关键的措辞细节

这是实测出来的，写在这里免得别人重新踩：

| 注入措辞 | 模型的实际行为 |
|---|---|
| "必须原话" | 短回一句就完了 |
| "必须原话照说" | 有时照搬，有时不 |
| **"这一轮必须原样发出去，一个字都别改" + 项目符号列出来** | **才会真的逐字照搬** |

而且**只在高档位用**。低档位用"参考，不用照抄"——强迫照抄会显得机械。

`examples/inject_to_llm.py` 里就是这么写的。

## 实测

档位递进：

```
你好       → 0 档 平静，1 句
你个傻逼    → 2 档 上火，3 句
滚         → 3 档 冒烟，4 句
你妈死了    → 5 档 炸了，8 句（跳级限制 2，3+2=5）
对不起     → 3 档 冒烟，4 句（安抚 -2）
```

时间衰减（每 10 分钟 -1）：

```
连骂两次 → 4 档
+10 分钟 → 3 档
+25 分钟 → 2 档
+50 分钟 → 0 档
```

## 限制

老实说：

- **纯规则，抓不到语境**。"你上次也是这么说的"——不知道这是翻旧账
- **单轴**。只有"愤怒/激动"一个维度。开心、难过要起第二个实例
- **关键词会误伤**。"笑死了"里的"死"会 +2（除非你把它加进白名单）
- **没有多语言**。规则是按中文写的

要更准的话，得叠一层小模型判断——但那就不是"零依赖零成本"了，是另一种取舍。
